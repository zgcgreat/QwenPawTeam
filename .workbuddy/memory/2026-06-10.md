### 登录页加载慢分析
- 根本原因：**未启用 gzip 压缩** — uvicorn 默认不压缩，ui-vendor.js 8.2MB 原样传输
  - gzip 后 ui-vendor 仅 2.3MB（减少 72%）
  - index.js 1.6MB → gzip 440KB（减少 73%）
- 前端资源总大小：14MB（242 JS + 59 字体 + 2 CSS）
- `PluginProvider` 在 AppInner 中阻塞渲染：`if (pluginsLoading) return null`
  - loadAllPlugins() 需等后端 `/api/frontend_plugin` 返回 + 下载 CloudPaw(63KB) + QwenPawPet(20KB) 插件
- 登录页本身 TTFB 仅 ~200ms，DOM 加载 ~600ms，问题在网络传输大文件无压缩

### 登录 401 问题根因与修复 (commit 279fc3bc)
- **根因**：多用户插件注册的 `/api/auth/*` 路由是**死路由**！
  - 上游 `routers/auth.py` 在 `_app.py:700` 模块级 `app.include_router(api_router, prefix="/api")` 注册
  - 多用户插件在 `_background_startup()` 异步注册 → 晚于上游
  - FastAPI 按路由列表顺序匹配 → 上游 `/api/auth/login` 先匹配 → 插件路由永远到不了
  - 前端 MuLoginPage 调 `/auth/login` 走上游，上游 `authenticate(username, password)` 对新用户直接返回 None → 401
- **修复**：在 `_app.py` 中 `app.include_router(api_router, prefix="/api")` 之后，若多用户启用则移除所有 `/api/auth/*` 路由
  - 这样后续插件注册的 `/api/auth/*` 路由能正常生效
  - 提供自动注册、动态字段、多用户状态等完整功能
- 登录完整链路：前端 MuLoginPage → `muAuthApi.login({username, password})` → `POST /api/auth/login` → router_extension.login() → `authenticate(password, username=xxx)` → 查找用户/自动注册 → 返回 token
