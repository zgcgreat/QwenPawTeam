## Phase 2: 多用户插件迁移方案设计（完成）

### 核心结论
上游新增了 `qwenpaw.plugins` 系统（PluginLoader + PluginRegistry + PluginApi），提供：
- `register_startup_hook` / `register_shutdown_hook`
- `register_http_router` / `register_provider`
- `register_prompt_section` / `register_control_command`
- `register_uninstall_hook` / `register_workspace_created_hook`

插件通过 `plugin.json` manifest 声明，入口 `plugin.py` 导出 `plugin` 对象，实现 `register(api)` 方法。

### 迁移策略
1. **后端**：将 `src/qwenpaw_plugins/multi_user/` 迁移为上游新插件格式
   - 在 `plugins/bundle/multi-user/` 创建 `plugin.json` + `plugin.py`
   - 原有 extension 文件整体搬迁到 `plugins/bundle/multi-user/`
   - 用 `api.register_startup_hook()` 替代 `_app.py` 中的手动激活
   - 用 `api.register_http_router()` 注册 auth 路由
   - 不再需要在 `_app.py` 中插入任何代码
2. **前端**：保持 `console/src/multi_user/` 独立
   - `console/src/api/authHeaders.ts` 保持多用户代理（import from multi_user）
   - `console/src/api/request.ts` 恢复使用上游的 `setHandle401` 机制（内联401改为可覆盖）
   - `App.tsx` / `Header.tsx` 保留多用户组件

### 关键设计决策
- **不再修改 `_app.py`**：上游的 `startup_hook` 机制让我们可以在插件中完成所有激活
- **AuthMiddleware 替换**：在 startup hook 中 patch auth 模块，让 `_app.py` 中 `app.add_middleware(AuthMiddleware)` 自动使用多用户版本
- **前端 authHeaders 代理**：`console/src/api/authHeaders.ts` 作为唯一入口，内部根据 MULTI_USER_ENABLED 分派
- **前端 401 处理**：恢复 `setHandle401` 机制，多用户在初始化时调用 `setHandle401` 覆盖默认行为
